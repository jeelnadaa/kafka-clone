Why Append-Only Logs?

Unlike relational databases that perform random B-Tree page writes, Kafka logs append strictly to the end of the file. Sequential disk I/O on modern storage drives achieves hundreds of megabytes per second, leveraging the operating system page cache without random seek penalties.

BINARY OFFSET INDEX

Why .index Files?

Scanning a large log file from byte zero to find an offset is inefficient. The broker writes a fixed 16-byte index entry [8B offset | 8B physical byte position] every message. A binary search immediately finds the exact byte to seek to in O(log N) time.

NON-DESTRUCTIVE READS

Why Consumer Offsets?

Traditional queues delete messages as consumers process them. In Kafka, messages are immutable and permanent. Multiple consumer groups can read the same stream independently at their own pace, or rewind (seek) to replay events anytime.
